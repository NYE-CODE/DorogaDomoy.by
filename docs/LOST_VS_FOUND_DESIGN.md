# Разделение «Потерян» / «Найден»: анализ и предложение по реализации

## 1. Текущее состояние (без админки)

### Модель и API
- **Одна сущность** `Pet` с полем `status: 'searching' | 'found'`.
- Одинаковые поля для обоих статусов: фото, тип животного, порода, окрас, пол, возраст, описание, город, **одна точка на карте** (location_lat/lng), контакты автора.
- Смысл точки: для «потерян» — где потеряли/последнее место; для «найден» — по сути то же поле, но семантика «где нашли» нигде не подчёркнута.

### Форма создания/редактирования
- **Одна форма** `PetForm`: в шаге 1 выбирается статус (Ищут / Найден), дальше те же шаги — тип, порода, цвет, пол, возраст → описание, фото, адрес, карта.
- Нет отдельных полей «дата потери» / «дата находки», нет поля «где сейчас содержится» для найденного.

### Карта и список
- Один слой маркеров; цвет по `status`: красный (searching), синий (found).
- Фильтры: по статусу (оба / ищут / найден), тип, порода, период и т.д.
- В списке и в карточке — один и тот же тип карточки, различается только бейдж и текст («Помогите найти» / «Ищем хозяина»).

### Специфика «потерян»
- **Sightings** («видел похожее») доступны **только** для `status === 'searching'`: пользователи отмечают на карте место, где видели животное; владелец получает уведомление в Telegram.

### Матчинг
- В **Telegram-уведомлениях** уже есть перекрёстный матч: у пользователя с объявлением «потерян» при появлении «найден» рядом (и наоборот) отправляется уведомление. Матч по: радиус из настроек, тип животного, противоположный статус. Порода/окрас в запросе не используются.

### Итог по пробелу
- Нет **смыслового разделения**: «найден» не имеет «места находки» и «даты находки» как первых сущностей.
- Нет **быстрого матчинга в UI**: на карточке объявления нет блока «возможные совпадения» (потерян ↔ найден по месту + тип + порода/окрас).
- Форма одна — нельзя сделать минимальную форму «Нашёл животное: место, дата, фото, контакт» без лишних полей.

## 2. Варианты реализации

### Вариант A: Две сущности (LostPet / FoundPet)
- Отдельные таблицы `lost_pets` и `found_pets`, отдельные API (`/lost`, `/found`), отдельные типы на фронте.
- **Плюсы:** чёткое разделение, свои поля под каждый сценарий, проще валидация и индексы под матчинг.
- **Минусы:** дублирование логики (фото, модерация, автор, архив), два списка на карте, сложнее общая статистика и общий «поток» объявлений.

### Вариант B: Одна сущность Pet с типом объявления (рекомендуемый)
- Оставить одну таблицу `pets`, ввести **тип объявления** `ad_type: 'lost' | 'found'` (по смыслу заменить или дополнить текущий `status`).
- Добавить опциональные поля: `lost_at`, `found_at` (даты), `where_kept` (где сейчас: у нашедшего / передержка / ветклиника — только для found).
- Формы, карта и карточки **различаются по `ad_type`**, но API и модель общие.
- **Плюсы:** один список/карта с фильтром по типу, одна модерация, одна архивность, проще миграция.
- **Минусы:** в одной таблице смешаны два сценария — нужна дисциплина в коде (условия по `ad_type`).

Далее описание — в рамках **варианта B** (одна сущность, два типа с разной семантикой и UI).

---

## 3. Отличия форм

### Форма «Потерян» (ad_type = lost)
- **Поля как сейчас:** статус не выбирается (всегда «потерян»), тип животного, порода, окрас, пол, возраст, описание, фото, адрес, точка на карте, контакты.
- **Добавить (опционально):**
  - **Дата потери** (`lost_at`) — дата/день, когда пропал. Подсказка: «Когда примерно потеряли?» Для матчинга с «найден» по времени.
- **Семантика места:** явная подпись «Место, где потеряли / последнее место, где видели» (то же поле location + city).

### Форма «Найден» (ad_type = found)
- **Упрощённый первый шаг:** не «статус», а сразу тип животного (кошка/собака/другое), по возможности порода и окрас — то, что нашедший может описать по виду.
- **Обязательно:**
  - **Место находки** — адрес + точка на карте. Подпись: «Где нашли (адрес или точка на карте)».
  - **Дата находки** (`found_at`) — когда нашли. Критично для матчинга.
- **Описание:** краткое (где нашли, в каком состоянии, особые приметы).
- **Фото:** хотя бы одно (как сейчас).
- **Опционально:**
  - **Где сейчас** (`where_kept`): у меня / на передержке / в ветклинике / в приюте. Выпадающий список или радиокнопки.
- Контакты — как сейчас (автор = нашедший).

Итог: форма «Найден» визуально и по полям — отдельный поток (другой заголовок, другой порядок полей, обязательные «место находки» и «дата находки»), но те же сущности в API (Pet с ad_type и доп. полями).

---

## 4. Поля в модели (вариант B)

В таблице `pets` (или в типах на фронте):

- Сохранить: `status` для обратной совместимости или заменить на `ad_type: 'lost' | 'found'` и везде использовать его.
- Добавить (nullable для старых записей):
  - `lost_at` (DATE/DATETIME) — для объявлений «потерян».
  - `found_at` (DATE/DATETIME) — для объявлений «найден».
  - `where_kept` (VARCHAR) — для «найден»: `at_finder` / `foster` / `vet` / `shelter` / null.

Остальное (location_lat/lng, city, description, photos, author, moderation, archive) без изменений.

---

## 5. Карта

- **Один слой** маркеров, но два типа точек:
  - **Потерян** — красный маркер (как сейчас searching).
  - **Найден** — синий маркер (как сейчас found).
- **Фильтр в шапке/панели:** «Показать: Все | Только потерянных | Только найденных». Уже есть по сути (фильтр по status), достаточно переименовать в «Тип объявления» и при необходимости разделить визуально (иконки «потерян» / «найден»).
- **Кластеры:** при группировке маркеров в кластере можно показывать две цифры: «3 потерянных, 2 найденных» или два мини-бейджа по цвету.
- **Попап маркера:** коротко тип животного, тип объявления (потерян/найден), дата (lost_at или found_at), ссылка на карточку. Для «найден» — опционально «где сейчас».

Отдельный «слой только найденных» можно не делать — достаточно фильтра; при желании позже можно добавить переключатель слоёв (потерянные / найденные) для очень плотной карты.

---

## 6. Карточка объявления (страница детали)

### Общее
- Баннер вверху: для потерянного — «Помогите найти», для найденного — «Ищем хозяина».
- Фото, описание, контакты, карта с одной точкой (место потери или место находки) — как сейчас.

### Только для «потерян»
- Показать «Дата потери» (если есть).
- Блок **«Видел похожее»** (sightings) и кнопка «Отметить на карте» — без изменений.

### Только для «найден»
- Показать **«Дата находки»** и **«Где сейчас»** (если указано).
- Новый блок: **«Возможные совпадения»** (быстрый матчинг):
  - Запрос к API: «потерянные в радиусе N км от этой точки (или в том же городе) с тем же типом животного», опционально фильтр по породе/окрасу.
  - Список карточек (компактных): фото, тип, порода, дата потери, ссылка на объявление «потерян». Цель — нашедший или волонтёр быстро видит, кого мог найти, и переходит к контактам.

### Обратная связь для «потерян»
- На карточке объявления «потерян» — блок **«Недавно найденные рядом»**:
  - Объявления «найден» в радиусе (или в том же городе) с тем же типом животного.
  - Компактные карточки со ссылками, чтобы владелец мог сам проверить совпадения.

Так матчинг становится явным в интерфейсе, а не только в Telegram.

---

## 7. Быстрый матчинг (логика и API)

### Правила
- **Для объявления «найден»** ищем **«потерянных»**: в радиусе (например 5–15 км от точки находки) или в том же `city`, тот же `animal_type`, опционально пересечение по `breed` или `colors`; можно сортировать по `lost_at` (ближе к дате находки — выше).
- **Для объявления «потерян»** ищем **«найденных»**: те же условия (радиус или город, тип, опционально порода/окрас), сортировка по `found_at`.

### API (пример)
- `GET /pets/{id}/matches?radius_km=10&limit=20`  
  Возвращает список подходящих противоположных объявлений (поля для превью: id, photos[0], animal_type, breed, city, lost_at/found_at, link).  
  Backend считает расстояние от `pets.location` до переданного id (или от id до остальных), фильтрует по ad_type, городу/радиусу, типу, при желании по породе/цвету.

### Кэш и производительность
- Для списка матчей можно кэшировать на 5–15 минут по `pet_id`, так как новые объявления не появляются каждую секунду.
- Индексы: по (ad_type, city, animal_type), по (location_lat, location_lng) или использование spatial индекса при росте данных.

---

## 8. Отличия в списках и «Мои объявления»

- **Главная (карта + список):** фильтр «Тип объявления» = все / потерянные / найденные. Карточки в списке — как сейчас, с бейджем «Потерян» / «Найден» и при желании датой (lost_at / found_at).
- **Мои объявления:** одна вкладка «Мои объявления» с подфильтром или двумя блоками: «Потерянные» и «Найденные» (по ad_type), без изменения логики модерации (pending/approved/rejected).

---

## 9. Уведомления (Telegram) и Sightings

- **Уведомления «новое объявление рядом»:** оставить как есть — перекрёстный матч по статусу (lost ↔ found), радиус, тип. При введении `ad_type` просто подставлять его вместо `status`.
- **Sightings:** только для объявлений «потерян» — без изменений (уже привязаны к status === 'searching').

---

## 10. Краткий чеклист внедрения (без админки)

1. **Модель и миграция:** добавить `lost_at`, `found_at`, `where_kept`; ввести или заменить на `ad_type` ('lost' | 'found'), заполнить из текущего `status`.
2. **API:**  
   - обновить схемы создания/обновления (приём новых полей);  
   - добавить `GET /pets/{id}/matches` с фильтром по радиусу/городу и типу.
3. **Формы:**  
   - форма «Потерян»: добавить поле «Дата потери» (опционально);  
   - форма «Найден»: отдельный поток (или шаг 0 «Что создаём» → потерян/найден), обязательные «Место находки» и «Дата находки», опционально «Где сейчас».
4. **Карта:** оставить один слой, донастроить фильтр и подписи (потерян/найден), при желании — подпись в попапе с датой.
5. **Карточка объявления:** для «найден» — блок «Возможные совпадения» (потерянные рядом); для «потерян» — блок «Недавно найденные рядом».
6. **i18n и тексты:** разделить форму и карточки по типам (заголовки, плейсхолдеры, подписи полей).

После этого разделение «потерян» / «найден» будет не только статусом, а отдельным типом объявления с привязкой к месту находки/потери, датами и быстрым матчингом в интерфейсе.
