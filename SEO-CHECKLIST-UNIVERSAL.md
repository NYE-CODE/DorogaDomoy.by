# Универсальный SEO-чек-лист (Google + Яндекс)

Обезличенная версия: объединены два исходных чек-листа (технический чек-лист разработчика и аудит конкретного сайта). Всё, что было привязано к стеку, бренду, городу или нише, обобщено. Каждый пункт сверен с официальной документацией Google Search Central и Яндекс Вебмастера (ссылки — в конце).

## Честная рамка

- **Ни один чек-лист не гарантирует топ.** Позиции зависят от конкуренции, запроса, качества контента, ссылочного профиля и поведения пользователей. Google прямо пишет, что отправка sitemap, canonical и разметка — это подсказки, а не команды.
- Этот чек-лист закрывает то, что полностью в вашей власти: **чтобы сайт мог попасть в индекс, был понят поисковиком и не терял позиции из-за технических ошибок**. Выше этого уровня работает контент, доверие и внешние сигналы (разделы 6, 7, 9, 12).
- Плейсхолдеры: `{домен}`, `{регион}`, `{бренд}`, `{ниша}`.

**Приоритеты:** **P0**: без этого страница не индексируется или дублируется. **P1**: сильно влияет на выдачу и сниппет. **P2**: улучшение.

**Правило нулевого пункта.** Откройте исходный HTML страницы (`curl -s URL` или «Просмотр кода», не DevTools после загрузки). Если там нет уникального title, H1 и содержательного текста, страница зависит от рендеринга JS. Оба поисковика рендерят JS, но это отложено и не гарантировано (см. раздел 1).

## 1. Рендеринг: что видит робот

Факты: Google рендерит JS в headless Chromium, но в отдельной очереди и «может занять больше времени». Яндекс исполняет JS «на усмотрение робота», это бета-функция Вебмастера. Серверный рендеринг/пререндеринг рекомендуют оба.

- [ ] **P0.** Публичная страница отдаёт в первом HTML уникальные `<title>`, H1 и основной текст. Проверка: `curl -s URL`.
- [ ] **P0.** В исходнике достаточно содержательного текста: услуги/товар, факты, цены, адрес, условия. Важна полезность, а не объём. Google прямо заявляет, что **«предпочтительного количества слов» нет**.
- [ ] **P0.** H1 в первом HTML и после гидрации совпадают по смыслу (маркетинговый слоган не подменяет SEO-заголовок). Это защита от расхождения между тем, что видит робот до и после JS.
- [ ] **P0.** Если используется клиентский JS для title/description/canonical, итоговые значения **совпадают** с серверными. Google допускает JS-правки, но canonical из JS не должен отличаться от canonical в исходном HTML. Лучше задавать мета в HTML.
- [ ] **P0.** Ссылки, контент и мета не требуют действия пользователя для загрузки (клик, свайп, ввод). Google такой контент не загружает.
- [ ] **P0.** Корзина, чекаут, личный кабинет, thank-you и подобное закрыты через `noindex` **в исходном HTML или заголовке `X-Robots-Tag`**. Google пишет, что при виде `noindex` может пропустить рендеринг, поэтому JS-удаление или добавление `noindex` ненадёжно.
- [ ] **P0.** Сборка с пререндером падает, если источник данных (API) недоступен. Нельзя деплоить «пустые» страницы, которые отдают HTML главной.
- [ ] **P1.** Контент для робота и человека одинаков (без клоакинга).
- [ ] **P1.** Если на сайте SSR/пререндер, в Яндекс Вебмастере (Индексирование → Рендеринг страниц JavaScript) можно выбрать «Не рендерить». Это рекомендация самого Яндекса, чтобы не создавать лишнюю нагрузку.
- [ ] **P1.** Если контент грузится с задержкой, проверьте результат в «Проверка страницы» Вебмастера и при необходимости используйте `window.YandexRotorSettings`.
- [ ] **P1.** Размер HTML страницы не превышает 10 МБ (страницы больше не индексируются Яндексом).

## 2. HTTP, хост и статусы

Правильный код ответа важнее любого мета-тега.

- [ ] **P0.** HTTP → HTTPS серверным редиректом 301. Для Яндекса `rel="canonical"` для смены http↔https **не поддерживается**, нужен редирект.
- [ ] **P0.** Один главный хост (www или apex): второй редиректит 301. Яндекс допускает canonical для www↔apex, но сам рекомендует редирект как более надёжный.
- [ ] **P0.** Несуществующий URL отдаёт **404 или 410**, не 200 с текстом «не найдено» (soft 404). Для SPA без серверной маршрутизации Google допускает запасные способы: JS-редирект на URL, который реально отдаёт 404, или `noindex` на странице ошибки. Но серверный 404 надёжнее.
- [ ] **P0.** SPA-fallback (`try_files … /index.html`) не должен отдавать главную на неизвестные адреса. Для каждого индексируемого URL: свой title и canonical, а не дубль главной.
- [ ] **P0.** Staging/preview закрыты Basic Auth или `noindex`. Не полагайтесь на «секретный URL» и **не используйте для этого только robots.txt**: Google и Яндекс могут индексировать закрытый в robots.txt URL, если на него есть ссылки.
- [ ] **P1.** Единая политика слэша и регистра: вариант не по правилам редиректит 301. Google считает URL **чувствительными к регистру**.
- [ ] **P1.** Карта редиректов для переездов и смены slug: старый URL → 301 на аналогичный новый (не всё на главную).
- [ ] **P1.** Удалённый товар/страница: 404/410 или 301 на реальную замену. Пустые технические выдачи (поиск без результата) закрыты `noindex`.
- [ ] **P1.** `robots.txt` и `sitemap.xml` отвечают 200 на GET (и желательно HEAD, это практическая проверка для мониторингов, а не требование поисковиков).
- [ ] **P1.** Content-Type: HTML `text/html; charset=utf-8`, XML sitemap `application/xml` (или `text/xml`), robots `text/plain`; кодировка UTF-8.
- [ ] **P1.** Цепочки редиректов короткие. Googlebot следует до 10 хопов; 301/308 — сильный сигнал, 302/307 — слабый.
- [ ] **P1.** Сервер не отдаёт 5xx/4xx на нормальных страницах. Google и Яндекс снижают скорость обхода при 5xx/429; Яндекс удаляет из поиска страницы с 4xx/5xx. При временных проблемах (например, сбой CMS) Яндекс советует отдавать 429, чтобы страница не выпала, но при долгом 429 скорость обхода снижается.
- [ ] **P2.** Мобильная и десктопная версии отдают одинаковый статус (для m-dot критично).

## 3. Обход: robots.txt и sitemap

- [ ] **P0.** `robots.txt` в корне, отвечает 200, не больше 500 КБ (лимит Яндекса), без кириллицы (домены в Punycode, пути в percent-encoding).
- [ ] **P0.** В `robots.txt` указан абсолютный `Sitemap: https://{домен}/sitemap.xml`.
- [ ] **P0.** Закрыты от обхода служебные разделы (админка, API, корзина, внутренний поиск, фильтры-дубли). **Не закрывайте CSS/JS/изображения**, нужные для рендеринга.
- [ ] **P0.** Помните: `Disallow` ≠ «удалить из индекса». Для исключения из поиска нужен `noindex` (мета или `X-Robots-Tag`), и страница **не должна** быть закрыта в robots.txt, иначе робот не увидит `noindex`.
- [ ] **P0.** В sitemap только индексируемые канонические страницы с кодом 200: без корзины, редиректов, 404, `noindex`, UTM, превью, пагинации-дублей.
- [ ] **P0.** Фильтры и параметры не в sitemap, если у них нет отдельной посадочной с уникальным текстом (иначе ЧПУ-страница или canonical на категорию).
- [ ] **P1.** Sitemap: UTF-8, абсолютные URL, ≤50 000 URL и ≤50 МБ (без сжатия) на файл. Больше — sitemap index. Лимиты одинаковы у Google и Яндекса.
- [ ] **P1.** Sitemap обновляется автоматически при добавлении/удалении страниц (генерация на деплое или динамически).
- [ ] **P1.** `lastmod` = реальная дата значимого изменения. Google использует его, только если он стабильно достоверен. `changefreq` и `priority` Google **игнорирует** (Яндекс `priority` принимает как подсказку).
- [ ] **P1.** Для Яндекса параметры, не влияющие на контент (`utm_*`, `ref`, `sid` и т.п.), описаны директивой `Clean-param`. Она лучше, чем `Disallow`, потому что передаёт накопленные показатели основному URL. Метки `utm_*`, `ysclid`, `yrclid` Яндекс убирает автоматически.
- [ ] **P1.** Не пытайтесь регулировать скорость обхода через `Crawl-delay`: Яндекс игнорирует его с 2018 года. Используйте «Скорость обхода» в Вебмастере.
- [ ] **P1.** Число URL в sitemap ≈ числу реально существующих страниц.
- [ ] **P2.** Image/video sitemap для сайтов, где медиа важны для поиска.

## 4. HTML каждой публичной страницы

- [ ] **P0.** Уникальный `<title>` на странице: основной запрос + уточнение (регион/ниша) + бренд. Без шаблонных одинаковых заголовков, без перечисления ключей. Google: нет лимита длины, но обрезает под ширину экрана. Бренд — одним коротким блоком в начале или конце через разделитель.
- [ ] **P0.** Title написан на том же языке и алфавите, что и основной контент (иначе Google может подменить заголовок).
- [ ] **P0.** Уникальный `meta description`: факты + польза + призыв, без перечня ключевых слов. Длина **не регламентирована** Google (обрезается под ширину); ориентир 140–160 символов — только практическая эвристика. Google может заменить его фрагментом из контента.
- [ ] **P0.** `rel="canonical"` на каждой странице: абсолютный URL **на саму себя** (или на реальный основной вариант). Не на главную. Canonical — подсказка, а не команда.
- [ ] **P0.** На публичных страницах нет `noindex`. На служебных страницах и 404 — `noindex`.
- [ ] **P0.** Один осмысленный основной заголовок H1, совпадающий с интентом страницы («Установка X в {регион}», а не «Услуги»). Google требует, чтобы главный заголовок был заметно выделен; правило «ровно один H1» — общепринятая практика, а не требование.
- [ ] **P0.** Верификация в Google Search Console и Яндекс Вебмастере (мета-тег, файл или DNS).
- [ ] **P1.** `<html lang="…">` корректен (для пользователей и доступности). **Google не использует `lang` и `hreflang` для определения языка** — определяет по тексту.
- [ ] **P1.** `hreflang` — только при реальных языковых/региональных версиях: каждая версия ссылается на все, включая себя; абсолютные URL; код = язык (ISO 639-1) + опционально страна (ISO 3166-1 Alpha 2); код страны один — недопустим; `UK`, `EU` не работают; рекомендуется `x-default`.
- [ ] **P1.** `<meta name="viewport" content="width=device-width, initial-scale=1">` присутствует.
- [ ] **P1.** Open Graph и Twitter Card (`og:title/description/url/type/image`) — для превью в соцсетях и мессенджерах, **не фактор ранжирования**. `og:image` — абсолютный URL, релевантная картинка высокого разрешения (не логотип и не favicon). Google также использует `og:image` как подсказку для превью.
- [ ] **P2.** `meta keywords`: Google не использует его, Яндекс называет как возможный сигнал; не тратьте время.
- [ ] **P2.** Если нужно закрыть сниппет/кэш: `nosnippet`, `max-snippet`, `noarchive` (`noarchive` поддерживает и Яндекс).

## 5. Структура, URL и внутренние ссылки

- [ ] **P0.** Навигация и внутренние ссылки — настоящие `<a href="…">`. Google извлекает ссылки только из `<a>` с `href`; `onClick`/`routerLink` без `href`, `javascript:` и `#`-роуты ненадёжны.
- [ ] **P0.** Один интент = один отдельный URL. Якорь `#раздел` не ранжируется как отдельная страница.
- [ ] **P0.** SPA-маршрутизация — через History API, не через `#`-фрагменты (Google не поддерживает фрагменты для смены контента).
- [ ] **P0.** Человекочитаемые URL со словами, не UUID и не ID-цифры; слова разделены дефисами (не подчёркиваниями); один регистр (обычно нижний); минимум параметров; без session ID в URL. Используйте язык аудитории (кириллицу — в percent-encoding в `href`).
- [ ] **P1.** Анкоры осмысленные и краткие (не «Подробнее» на всех карточках, не «кликните здесь»).
- [ ] **P1.** Важные разделы (контакты, услуги/каталог, политика, о компании) доступны из меню/подвала в HTML без JS.
- [ ] **P1.** Каждая важная страница достижима по ссылкам с других страниц (нет «страниц-сирот», которые есть только в sitemap).
- [ ] **P1.** H2/H3 отражают структуру страницы; в тексте есть конкретика: цены, условия, сроки, адрес, для кого.
- [ ] **P1.** Пагинация и фильтры не плодят тонкие дубли. Google рекомендует ограничивать бесконечные пространства URL (комбинации фильтров, календари) через `robots.txt`/`nofollow` и нормальную faceted-навигацию; для бесконечной прокрутки должны существовать URL страниц (`?page=N`).
- [ ] **P2.** Хлебные крошки в HTML и `BreadcrumbList`.

## 6. Страницы-интенты и контент

- [ ] **P0.** Собрана семантика (Яндекс Вордстат + Google Keyword Planner/GSC) и разложена по страницам: один кластер запросов → одна страница. Не плодить тонкие дубли.
- [ ] **P0.** На каждой странице есть **ответ на задачу пользователя**, а не тексты ради поисковика. Google: оценивает полезность, оригинальность, полноту; предупреждает против массовой генерации контента «для поиска», подмены дат «для свежести» и переписывания чужого без добавленной ценности.
- [ ] **P0.** Контент уникален и не копирует конкурентов/источники; даёт добавленную ценность (данные, опыт, условия, цены, фото, примеры).
- [ ] **P1.** Для коммерческих страниц — реальные данные: цены, условия, адрес, график, наличие. Не выдумывать цифры.
- [ ] **P1.** Карточки товаров/услуг/вакансий имеют полный набор фактов и свой URL.
- [ ] **P1.** Пустые состояния (каталог пуст, нет результатов) обработаны: не 200 «успех» в индексе, есть путь для пользователя.
- [ ] **P1.** Удалённый контент: не оставлять «мёртвые» страницы со статусом 200.
- [ ] **P2.** Информационные материалы (статьи, FAQ, кейсы, отзывы) под «сомнения» и вопросы аудитории: только если их можно сделать полезными и честными.

## 7. Доверие (E-E-A-T) и юридическая прозрачность

Google: E-E-A-T — не отдельный фактор ранжирования, но система использует признаки доверия; **доверие — главное**, особенно для YMYL-тем (здоровье, финансы, безопасность, юридические вопросы).

- [ ] **P0.** Понятно, кто стоит за сайтом: название юрлица/ИП, реквизиты, контакты, адрес — в подвале и/или на странице контактов.
- [ ] **P1.** Страница «О компании» (кто вы, опыт, команда, лицензии/разрешения, если применимо).
- [ ] **P1.** Юридические страницы (политика конфиденциальности, оферта/условия) без заглушек и «lorem ipsum».
- [ ] **P1.** У экспертного контента указан автор (byline) со ссылкой на страницу автора. **Не фабрикуйте профили и credentials** — Google считает обман признаком низкого качества.
- [ ] **P1.** Отзывы — только реальные, с источником. Не размечайте фейковые отзывы и рейтинги (риск ручных мер).
- [ ] **P1.** Если используется ИИ/автоматизация для контента, есть редакторская проверка; раскрытие уместно там, где читатель ожидает знать «как это создано».
- [ ] **P2.** Скриншоты/сканы лицензий, договор-образец, условия — только подтверждённые.

## 8. Структурированные данные

Не поднимают позиции напрямую; дают право на расширенный сниппет и помогают понять сущность. Google не гарантирует показ даже при валидной разметке.

- [ ] **P1.** Формат — JSON-LD (рекомендован Google). Разметка отражает **видимый** на странице контент (нельзя размечать скрытое или нерелевантное).
- [ ] **P1.** Заполнены все обязательные свойства нужного типа; тип максимально специфичный (`Organization` → подтип, `LocalBusiness` → конкретный подтип).
- [ ] **P1.** `Organization`/`LocalBusiness`: название, адрес (`PostalAddress`), телефон, часы (`openingHoursSpecification`), координаты (`geo`, не менее 5 знаков после запятой), `sameAs` на реальные профили.
- [ ] **P0.** NAP (название, адрес, телефон) идентичны в разметке, в HTML (подвал/контакты) и в картографических карточках (Яндекс Бизнес / Google Business Profile).
- [ ] **P1.** `Product`: имя, бренд, цена, валюта, наличие, URL, изображение. `aggregateRating` — только из реальных отзывов, видимых на странице.
- [ ] **P1.** Другие типы по контенту: `Article`, `BreadcrumbList`, `JobPosting`, `VideoObject`, `FAQPage` и т.д. Каждый — по требованиям Google к конкретному типу. Перед внедрением проверьте актуальный список поддерживаемых типов в документации Google: набор расширенных результатов меняется.
- [ ] **P1.** Нет дублирующей разметки (prerender + клиентская вставка). Проверка: Rich Results Test и валидатор микроразметки Яндекса.
- [ ] **P1.** Разметка не закрыта `noindex`/robots; изображения из разметки доступны для обхода.
- [ ] **P2.** Мобильная и десктопная версии содержат одинаковую разметку (для mobile-first).

## 9. Локальное SEO (если есть привязка к региону)

- [ ] **P0.** Адрес, телефон, часы работы — **текстом в HTML**, не только картинкой/iframe карты. Яндекс прямо требует полный адрес с индексом и телефонным кодом и не рекомендует размещать контакты только изображением.
- [ ] **P0.** Телефон кликабелен (`tel:`), регион присутствует в title и первом абзаце главных страниц.
- [ ] **P0.** Яндекс Бизнес: карточка организации создана и одобрена; указан сайт (главная страница **без UTM**) и регион; адрес сайта записан так же, как в Вебмастере (с/без `www`, http/https).
- [ ] **P0.** Яндекс Вебмастер → «Представление в поиске → Региональность»: задан регион (ссылка на страницу, где регион подтверждён, например «Контакты»; модерация до ~1–2 недель). Для одного сайта выбирайте регион, охватывающий все ваши адреса/зоны доставки, и перечислите их на сайте.
- [ ] **P1.** Google Business Profile: карточка по реальному адресу (не виртуальный офис), одна карточка на локацию, данные = сайт.
- [ ] **P1.** Если несколько филиалов: на сайте перечислены все адреса; для региональных поддоменов — уникальный контент (дубли будут склеены роботом Яндекса).
- [ ] **P1.** Нет геопереадресации, из-за которой робот видит одну региональную версию (Яндекс обходит с IP одного региона): все страницы доступны роботу независимо от IP.
- [ ] **P2.** Цитирование в справочниках: ссылка ведёт на актуальный сайт и совпадает по NAP.
- [ ] **P2.** Коллизия брендов: в title добавляйте нишу/регион, если название занято чужими доменами.

## 10. Изображения, видео, шрифты

- [ ] **P1.** Содержательные изображения — `<img>` (не CSS background; Google не индексирует CSS-картинки); у важных — уникальный `alt` без перечисления ключей. У декоративных `alt=""`.
- [ ] **P1.** Описательные имена файлов (`black-kitten.jpg`, а не `IMG0023.jpg`), стабильные URL картинок (без случайных параметров при каждой загрузке).
- [ ] **P1.** Форматы, поддерживаемые Google: BMP, GIF, JPEG, PNG, WebP, SVG, AVIF. Для `srcset`/`<picture>` обязателен fallback `src`.
- [ ] **P1.** LCP-изображение: приоритетная загрузка (`fetchpriority="high"`/preload), заданные `width`/`height`, адаптивные размеры (`srcset`); ниже первого экрана — lazy-loading, который не требует взаимодействия.
- [ ] **P1.** Мобильная версия содержит те же изображения/alt, что и десктопная.
- [ ] **P1.** Фавикон:
  - Google: квадрат (1:1), минимум 8×8, рекомендуется **>48×48**; один на хост; форматы BMP/GIF/ICO/PNG/JPEG/PPM/TIFF; `<link rel="icon">` на главной; не блокировать в robots.txt; стабильный URL; показ не гарантирован.
  - Яндекс: файл `favicon` в корне; **SVG** (рекомендуется) или 120×120 / 32×32 / 16×16; 200 OK без редиректа; корректный `type`; обновление в поиске ~ до 2 недель.
- [ ] **P2.** Фоновое видео не единственный LCP-элемент: poster + текст в HTML.

## 11. Скорость и мобильная версия

- [ ] **P1.** Core Web Vitals (по полевым данным, 75-й перцентиль, мобильные и десктоп отдельно):
  - LCP ≤ 2,5 с
  - INP ≤ 200 мс
  - CLS ≤ 0,1
  - Лаб-инструмент Lighthouse INP не измеряет, смотрите TBT как косвенный показатель.
- [ ] **P1.** Адаптивный дизайн (рекомендован Google); одинаковый контент, мета-теги и структурированные данные на мобильной и десктопной версиях. Google индексирует **мобильную** версию.
- [ ] **P1.** Code-splitting маршрутов, ленивая загрузка ниже первого экрана, без лишних тяжёлых библиотек на лендинге.
- [ ] **P1.** Шрифты: self-host или preload критичных, `font-display`, поднабор для кириллицы.
- [ ] **P1.** Долгое кэширование статики с fingerprint в имени файла (Google WRS может использовать устаревшие JS/CSS при плохом кэшировании).
- [ ] **P2.** Быстрый TTFB (статика с диска/CDN).
- [ ] **P2.** Счётчики аналитики не блокируют отрисовку контента.

## 12. Внешние сигналы (ссылки, бренд, поведение)

Здесь нет «технической галочки», но это часть реального ранжирования.

- [ ] **P1.** Ссылки получайте естественно: полезный контент, партнёрства, упоминания, каталоги отрасли.
- [ ] **P0 (запрет).** Не покупайте и не продавайте ссылки ради ранжирования, не используйте автоматические сети ссылок, массовые каталоги, ссылки в виджетах/подвалах чужих сайтов. Google относит это к link spam; Яндекс — к нарушению принципов с ограничениями в ранжировании.
- [ ] **P1.** Платные/партнёрские/рекламные ссылки на вашем сайте: `rel="sponsored"` (или `nofollow`); пользовательские: `rel="ugc"`.
- [ ] **P0 (запрет).** Не накручивайте поведенческие факторы. Яндекс прямо называет накрутку поисковым спамом, риск — серьёзные ограничения в ранжировании.
- [ ] **P2.** Яндекс.Метрика / GA подключены (с учётом требований к согласию на cookie в вашей юрисдикции). Яндекс называл Метрику важным, но не единственным источником сигналов качества; счётчик должен работать (Вебмастер предупреждает о неработающем).

## 13. Деплой и регрессия

SEO чаще всего ломается при выкладке.

**Минимум на каждый деплой:**

1. `curl` главной, случайной карточки/статьи: свой title, H1, canonical (не копия главной).
2. `robots.txt` и `sitemap.xml` отдаются как текст/XML, **не** `<!DOCTYPE html>`.
3. Несуществующий URL → 404 (`curl -I {домен}/qwerty-несуществует`).
4. Вариант со/без слэша и `http`/`www` → 301 на главный адрес.
5. Новая сущность (товар, статья, вакансия) есть в sitemap и имеет свой HTML.
6. Staging закрыт; в продакшене нет `noindex`, оставшегося после тестов.
7. Нет `Disallow: /` в продакшн-robots.txt.

- [ ] **P0.** Автотесты SEO-консистентности (title, H1, canonical, sitemap, 404, статусы) в CI.
- [ ] **P1.** Число URL в sitemap ≈ числу собранных страниц.
- [ ] **P1.** Подписаться на уведомления GSC и Вебмастера.

## 14. Запуск и мониторинг (после выкладки)

- [ ] **P0.** Sitemap добавлен в Google Search Console и Яндекс Вебмастер (Яндекс обрабатывает файл до двух недель).
- [ ] **P0.** В Вебмастере указан регион, если сайт региональный (раздел 9).
- [ ] **P0.** Запрошена индексация ключевых URL (URL Inspection в GSC; «Переобход страниц» в Вебмастере). Google пересканирует изменения «от нескольких дней до нескольких недель».
- [ ] **P1.** Регулярно просматривать: «Страницы → Не в индексе» (GSC), «Статистика обхода» и «Диагностика» (Вебмастер), отчёт Core Web Vitals, Soft 404, дубликаты, ручные меры и нарушения.
- [ ] **P1.** После исправления Soft 404/ошибок нажать «Проверить исправление» в GSC.
- [ ] **P1.** Проверить превью шаринга (Telegram/мессенджеры, Facebook Sharing Debugger).
- [ ] **P1.** Отслеживать поисковые запросы и позиции по кластерам, а не по одному «главному» слову.
- [ ] **P2.** Раз в квартал: ревизия sitemap, редиректов, «битых» ссылок, устаревшего контента, обновление дат только при реальных изменениях.

## 15. Сводка: частые поломки и проверка

| Симптом | Причина | Проверка |
|---|---|---|
| Карточки в выдаче как дубль главной | SPA-fallback отдаёт `index.html`, нет пререндера карточки | `curl` URL карточки: title и canonical |
| Яндекс/Google видят пустую витрину | Контент появляется только после JS | Сравнить view-source и DOM; «Проверка страницы» в Вебмастере |
| H1 «правильный» в коде, в индексе слоган | После гидрации H1 меняется | Сравнить исходник и отрендеренный DOM |
| Sitemap есть, страниц в индексе нет | Параметры/UUID/дубли, 200-страницы-пустышки, нет GSC/Вебмастера | GSC → «Не в индексе»; Вебмастер → «Статистика обхода» |
| URL закрыт в robots, но висит в выдаче | `Disallow` не удаляет из индекса | Убрать из robots.txt, поставить `noindex` |
| `noindex` «не срабатывает» | Задан только через JS или страница закрыта в robots.txt | Проверить исходный HTML/заголовок |
| Поиск по бренду есть, сайта нет | Нет сайта в картах/справочниках, нет верификации | Выдача по названию; Яндекс Бизнес / GBP |
| Неверный регион/нет геовыдачи | Не задан регион в Вебмастере или NAP не совпадает | Вебмастер → Региональность; сверка NAP |
| Падение трафика после редизайна | Изменились URL без 301, пропал контент на мобильной версии | Карта редиректов, сравнение мобильного и десктопного HTML |

## Что исправлено относительно исходных чек-листов

| Утверждение в исходниках | Результат проверки |
|---|---|
| «Google частично исполняет JS, Яндекс слабо» | Устарело: Google рендерит JS (evergreen Chromium) с задержкой; Яндекс тоже исполняет JS по своему решению (бета). SSR/пререндер остаётся лучшей практикой. |
| Description «140–160 символов» как требование | У Google **нет лимита**, это эвристика. Важно содержание и уникальность. |
| «Сотни слов» / «400–800 слов» | Google прямо заявляет, что предпочтительного количества слов нет. Важна полнота ответа. |
| «Google игнорирует `keywords`» | Подтверждено (Google). Яндекс упоминает `keywords` как возможный сигнал. |
| Favicon Google «>48 px» как требование | Требование: квадрат ≥8×8; **>48×48 рекомендуется**. |
| Яндекс favicon: 120×120 + SVG | Подтверждено: 120×120, 32×32, 16×16 или SVG (рекомендуется). |
| `og:image` ≥ 1200 px как SEO | Это не поисковое требование, а рекомендация для превью в соцсетях. |
| `og:locale` и `lang` для региона | Google не использует `lang`/`hreflang` для определения языка страницы; `og:locale` — для соцсетей. |
| Canonical вместо 301 | Подтверждено: canonical — подсказка. Для http→https Яндекс canonical не поддерживает. |
| `Disallow` для закрытия от индекса | Не удаляет из индекса. Нужен `noindex` (и доступность для робота). |
| `noindex` через клиентский JS | Google предупреждает: при `noindex` рендеринг может быть пропущен. Ставьте в исходный HTML/заголовок. |
| «Метрика — поведенческие факторы для Яндекса» | Яндекс называл Метрику важным, но не единственным источником сигналов (блог 2017). Накрутка запрещена и наказуема. |
| «E-E-A-T — критично для ниши» | Google: E-E-A-T не отдельный фактор; доверие — главное; усиленный вес для YMYL. |
| `lastmod` в sitemap | Google учитывает только достоверный `lastmod`; `changefreq`/`priority` игнорирует. |
| Конкретные стеки/nginx/FastAPI-детали | Обобщены: это практика реализации, а не требование поисковых систем. |
