# Анализ проекта DorogaDomoy.by и дорожная карта развития

## 1. Что есть сейчас

**DorogaDomoy.by** — веб-платформа для поиска пропавших домашних животных в Беларуси.

### Реализованный функционал
- **Карта и список** — Leaflet, маркеры по объявлениям, фильтры (тип, порода, статус, поиск, возраст объявления), выбор/определение города
- **Объявления** — создание/редактирование (фото, описание, порода, цвет, пол, возраст, статус «ищу»/«найден», город, точка на карте, контакты)
- **Модерация** — pending/approved/rejected, настройки платформы (требовать модерацию, лимит фото)
- **Роли** — user, volunteer, shelter, admin
- **Жалобы** — причины (spam, inappropriate, fake, duplicate, found, other), разбор админом
- **Архив** — причина архивации (вернулся домой, пристроен, в приют и т.д.) или удаление
- **Профиль** — имя, email, контакты (телефон, Telegram, Viber)
- **Статистика** — счётчики «ищут» / «найдено» по активным объявлениям

### Технологии
- **Frontend:** React 18, TypeScript, Vite 6, Tailwind v4, Leaflet, Radix UI
- **Backend:** FastAPI, SQLAlchemy, SQLite, JWT, bcrypt

## 3. Пробелы в текущем продукте

1. **Нет оповещений** — пользователь не получает уведомления о новых объявлениях в своём городе/радиусе или по критериям (тип, порода).
2. **Нет разделения «потерян» / «найден»** — одна сущность «объявление» со статусом; для «найден» удобнее отдельный тип с привязкой к месту находки и быстрым матчингом с «потерян».
3. **Нет печати/шаблонов** — нельзя сгенерировать листовку или плакат с QR на объявление.
4. **Нет AI/матчинга по фото** — сравнение «потерян» ↔ «найден» только вручную по карте и фильтрам.
5. **Нет интеграции с Telegram/соцсетями** — нет бота, нет шеринга в сторис/постах с превью.
6. **Волонтёры и приюты** — роли есть, но нет отдельного функционала (подписки на район, задачи, статистика по приютам).
7. **Мобильный опыт** — только адаптивная вёрстка, нет PWA (офлайн, push), нет нативного приложения.
8. **Доверие** — нет верификации автора (телефон/email), нет рейтингов/отзывов.

## 4. Рекомендуемый функционал (приоритеты)

### Высокий приоритет (сильно повышают ценность)

1. **Подписки и оповещения**
   - Подписка на город/район (и опционально тип животного, порода).
   - Уведомления: email и/или Telegram (ссылка на объявление).
   - Backend: таблица подписок, задача (cron/Celery) или webhook при создании/обновлении объявления.

2. **Тип объявления «Найден» и матчинг**
   - Явный тип: «Потерян» / «Найден» (или отдельная сущность FoundPet).
   - Для «Найден» — место находки, дата, краткое описание, фото.
   - На карте и в списке — фильтр «показать только потерянных» / «только найденных» и блок «Возможные совпадения» на карточке (по району + тип + порода/окрас).

3. **Печать листовки и шаблон плаката**
   - Кнопка «Распечатать листовку» на карточке объявления.
   - Генерация PDF или печатная версия страницы: фото, описание, контакты, QR на страницу объявления.
   - Опционально: шаблон под A4/половинку A4 для расклейки.

### Средний приоритет (уникальность и удержание)

4. **Telegram-бот**
   - Команды: «Потерял» / «Нашёл» → краткая форма (город, тип, фото, контакты) → создание объявления на сайте.
   - Подписка на район/город в боте → уведомления о новых объявлениях.
   - Ссылка на карту/карточку в каждом сообщении.

5. **Улучшенный шеринг**
   - Open Graph / Twitter Card для страницы объявления (красивое превью при шаре в соцсетях и мессенджерах).
   - Кнопки «Поделиться» (VK, Telegram, WhatsApp) с коротким текстом и ссылкой.

6. **PWA**
   - Service Worker, манифест, иконки.
   - Установка на главный экран, быстрый доступ к карте и «Мои объявления».
   - Опционально: push-уведомления в браузере (при наличии backend для push).

### Ниже по приоритету (дифференциация)

7. **AI-подсказки по фото (MVP)**
   - Загрузка фото → определение типа (кошка/собака/другое), породы и окраса (как подсказки, не обязательные).
   - Можно начать с внешнего API (например, разметка породы/окрас) или простой моделью на своей базе фото (обучение позже).
   - Дальше: «похожие объявления» по эмбеддингам фото (потерян ↔ найден).

8. **Волонтёры и приюты**
   - Для роли volunteer: «зона ответственности» (город/район), подписка на новые объявления в зоне, простая статистика (сколько объявлений помогли закрыть).
   - Для shelter: привязка объявления «передан в приют» к конкретному приюту, страница приюта со списком переданных животных.

9. **Доверие**
   - Верификация телефона (SMS) или email (ссылка).
   - Бейдж «Верифицирован» в профиле и на объявлении.
   - Опционально: отзывы после успешного возврата (только для закрытых объявлений).

10. **Мультиязычность**
    - Хотя бы русский + белорусский (и при необходимости английский) для охвата всей аудитории и гос. требований.

## 5. Как сделать продукт максимально уникальным

### Фокус на Беларусь
- **География:** только Беларусь (или БЕ + приграничные регионы) — точные города, области, при необходимости районы.
- **Контент:** советы именно для РБ (куда звонить, приюты, ветклиники, волонтёрские группы по регионам).
- **Язык:** RU + BY из коробки — выделит на фоне чисто русскоязычных сервисов.

### «Дорога домой» как сценарий
- Не просто «доска объявлений», а пошаговый сценарий: «Потерял» → «Создал объявление» → «Подписался на район» → «Получил уведомление о возможном совпадении» → «Нашёл».
- Акцент на быстром первом шаге: мини-форма в Telegram или на главной («Только город + фото + контакт»), детали — потом.

### Сообщество и волонтёры
- Публичная карта волонтёров и приютов (с их согласия).
- Рейтинг/благодарности волонтёрам, история «вернули домой» (анонимизированно).
- Годовой отчёт: сколько животных вернулось домой благодаря платформе (как у Pet911).

### Технологическая изюминка
- **AI по фото** даже в простом виде (подсказка породы/окраса или «похожие») даст сильный маркетинговый посыл.
- **QR на листовке** → сразу карточка объявления на карте — меньше ручного ввода.
- **Один клик «Возможное совпадение»** между объявлением «потерян» и «найден» по району + типу + визуалу (ручной матч сегодня, AI позже).

### Юридическая и этическая ясность
- Чёткие правила и рекомендации: что делать при находке, как передать в приют, как не нарушить права.
- Согласие на обработку данных и публикацию контактов — уже есть в terms, можно вынести короткую памятку в интерфейс.

## 6. Краткий план внедрения (по этапам)

| Этап | Срок (условно) | Что делать |
|------|----------------|------------|
| 1    | 1–2 недели     | Подписки на город/тип + email-уведомления при новом объявлении |
| 2    | 1–2 недели     | Тип «Найден» + блок «Возможные совпадения» на карточке (по району + тип + порода) |
| 3    | 1 неделя       | Печать листовки (шаблон + QR на объявление) |
| 4    | 2–3 недели     | Telegram-бот: создание объявления, подписка, уведомления |
| 5    | 1 неделя        | PWA + Open Graph для шеринга |
| 6    | 2+ недели      | AI: подсказка породы/окраса по фото или «похожие» объявления |

Дальше — развитие волонтёров/приютов, верификация, мультиязычность в зависимости от ресурсов и обратной связи пользователей.
